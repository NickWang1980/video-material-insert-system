# 部署指南

## 开发模式
1. 安装后端依赖：`pip install -r backend/requirements.txt`
2. 安装前端依赖：`cd frontend && npm install`
3. 一键启动：`scripts/start_all.bat` 或 `./scripts/start_all.sh`

访问：
- 前端：`http://localhost:5173`
- 后端：`http://localhost:8000`（OpenAPI：`/docs`）

---

## 生产模式
1. 构建前端：`cd frontend && npm run build`
2. 启动：`scripts/start_all.bat --prod` 或 `./scripts/start_all.sh --prod`
3. 访问：`http://localhost:8000/`
4. 如需单独启动后端（不走一键脚本）：`scripts/start_backend.bat --prod` 或 `./scripts/start_backend.sh --prod`

---

## 本版部署注意点
- 必须安装 `faster-whisper`（已在 `backend/requirements.txt`）。
- 机器需可执行 `ffmpeg` 与 `ffprobe`。
- 首次 ASR 运行会加载模型（`small/medium`），耗时与机器性能相关。

---

## 验收清单（本版）
- 源视频创建后可下载 `wav/flac` 音轨。
- 源视频条目可看到 ASR 状态：`pending/running/completed/failed`。
- 可预览上传 SRT 与 ASR SRT 的解析结果。
- 创建任务时可切换 `subtitle_source`，默认 `uploaded`。
- ASR 未完成时，任务使用 ASR 字幕会被后端拦截并返回提示。
- ASR SRT 文件已存在时，即使状态字段延迟，任务弹窗仍按可用字幕处理，不再误提示“暂无可用字幕”。
- 未上传 SRT 时仍可创建源视频条目，且前端会给出“开始模型识别字幕”提示。
- ASR 产出的字幕文件名与源视频条目名一致（`.srt`）。
- ASR 识别失败会自动重试（默认最多 3 次），也可在源视频库手动“重试识别”。
- 若任务长期停留在 75%，可重启后端后使用“恢复全部任务”；本版已修复 FFmpeg 管道阻塞并加入超时保护。
