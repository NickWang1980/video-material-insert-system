# 圆角画中画素材插入 实施记录

> 时间：2026-06-03 11:11:34 ｜ 分支：feature/5.0 ｜ 作者：Nicholas + Claude

## 一、需求背景

现有「素材插入系统」里，匹配命中的素材以 overlay 形式叠在源视频上，本质就是画中画(PiP)，但只能是**直角矩形**。

本次需求：**在现有模板/规则配置上，给每条素材规则多加一个选项**，让其二选一：

- **普通画中画**——保持现状，不做任何修改（默认值，保证零回归）
- **圆角画中画**——把素材裁成圆角矩形，并加一圈**可见描边**（可设：圆角半径 px、描边颜色、描边粗细 px）

不另做独立工具，全部复用现有 `build_ffmpeg_command()` 的 overlay/scale/透明度/并发/进度/取消/硬件编码机制。

> 备注：放弃了「FFmpeg 专家版规格」里的 `geq` 逐帧逐像素方案（极慢、与"零 CPU 开销"自相矛盾、`overlay_cuda` 吃不下 rgba、双 `-filter_complex` 非法）。改用「**预生成圆角遮罩 PNG + alphamerge + 描边 overlay**」，遮罩仅按尺寸缓存生成一次，每帧只做廉价的 alpha 合并与叠加。

## 二、技术方案

### 难点
当前 `scale=W:H:force_original_aspect_ratio=decrease` 输出像素尺寸不确定，而 `alphamerge` 要求遮罩与素材尺寸**完全一致**。

### 解决
**探测素材原始分辨率 → 自己算出精确缩放尺寸 → 用精确 `scale=ow:oh` → 按该尺寸生成并缓存遮罩/描边 PNG**。

- 复用 `video_service.probe_video()` 探测素材 `native_w/native_h`（按 material_path 缓存）。
- `s = min(max_w/native_w, max_h/native_h)`；`ow = round(native_w*s)`；`oh = round(native_h*s)`（与现有 decrease 拟合一致，但尺寸由我们掌控，避免 off-by-one）。
- `corner_mask_utils.get_corner_assets(settings, ow, oh, radius, border_w, color)` 用 Pillow 画：
  - 白色抗锯齿圆角矩形 alpha 遮罩（4× 超采样 + LANCZOS 降采样）
  - 透明底 + 描边色圆角描边框（中心透明，仅 border_w>0 时生成）
  - 缓存到 `data/cache/pip_masks/`，命中即跳过。

### 圆角分支 filter 子链
```
[idx:v] (trim/setpts) format=rgba, scale=ow:oh [mat]
[mat][maskin:v] alphamerge=shortest=1 [matr]          # 圆角：四角变透明
[matr][borderin:v] overlay=0:0:shortest=1 [matb]      # 描边框叠在上层（仅 border_w>0）
[matb] trim=duration=D, setpts=...+start/TB, colorchannelmixer=aa=opacity [ov]
```
- 遮罩/描边 PNG 作为额外 `-i -loop 1` 输入，索引在 materials + 音效**之后**分配（`mask_to_index`）。
- 「普通」分支代码原样不动。

## 四、兼容性 / 回归

- 新字段只进 `config_content` JSON 列，**无需建表 / 改库迁移**。
- 旧模板缺字段 → 默认「普通」→ filter 链与改动前完全一致，产物无差异。
- 描边粗细=0 时只圆角、不画框；圆角半径=0 且无描边时按普通处理。

## 五、验证

1. `corner_mask_utils` 单测：生成 PNG、校验尺寸 / 缓存命中。
2. `build_ffmpeg_command` 单测：含「圆角」规则时 filter_complex 含 `alphamerge`、遮罩 `-i` 输入索引正确；全「普通」时与基线一致。
3. 端到端：新建模板设「圆角 + 半径30 + 白描边3px」→ 跑任务 → 输出 MP4 肉眼确认。

## 六、环境备注

- 当前环境 Python 3.14.3，Pillow 11.3.0 已可用（无需走 numpy 备选）。
- GPU：解码/缩放/编码仍走现有 nvenc；圆角的 alphamerge/overlay 在 CPU，开销小（非逐像素表达式）。
