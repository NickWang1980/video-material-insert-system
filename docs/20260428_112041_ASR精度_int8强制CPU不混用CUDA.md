# ASR 精度修复：int8 不与 CUDA 混用

## 问题

[backend/app/services/asr_service.py:71](backend/app/services/asr_service.py#L71) 原逻辑：用户选 `int8` 且机器有 CUDA → 返回 `("cuda", "int8_float16")`。这是劣解：

- `int8_float16` 在 CUDA 上速度低于纯 `float16`，精度也不如；
- 失去了 int8 本来的内存优势（CTranslate2 在 GPU 上仍要 fp16 中间结果）；
- 用户选 int8 的意图通常是"机器没显卡时跑得动"，不是要让 GPU 兼用。

## 修改

[backend/app/services/asr_service.py:_resolve_device_compute](backend/app/services/asr_service.py)：当 `pref == "int8"` 时**始终返回 `("cpu", "int8")`**，不再受 CUDA 检测结果影响。

新分辨矩阵：

| 用户偏好 | CUDA 可用 | CUDA 不可用 |
|---|---|---|
| auto | cuda + float16 | cpu + int8 |
| **int8** | **cpu + int8** | **cpu + int8** |
| float16 | cuda + float16 | cpu + int8（自动回退） |
| float32 | cuda + float32 | cpu + float32 |

## 配套修改

- 前端 [frontend/src/views/Settings.vue](frontend/src/views/Settings.vue)：int8 选项标签由 "int8（最快、显存最省）" 改为 "int8（CPU 专用，无显卡时最快）"，避免误导。
- `resolved_compute_label` 的 docstring 示例同步更新。

## 验证

```python
import backend.app.services.asr_service as svc
svc._cuda_available_cache = True
for pref in ['auto', 'int8', 'float16', 'float32']:
    print(pref, svc._resolve_device_compute(pref))
# auto    -> ('cuda', 'float16')
# int8    -> ('cpu',  'int8')        ← 关键
# float16 -> ('cuda', 'float16')
# float32 -> ('cuda', 'float32')
```

## 涉及文件

- `backend/app/services/asr_service.py` — `_resolve_device_compute` + `resolved_compute_label` docstring
- `frontend/src/views/Settings.vue` — int8 选项标签

## 是否需要重启 / build

**需要：重启后端 + 前端热更新自动生效**

后端逻辑函数改动，必须重启 uvicorn。新选定的精度会在下一次 ASR 任务运行时生效；正在运行的转写不会受影响。
