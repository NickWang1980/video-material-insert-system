# 审计日志 + 数据库加密 + 操作历史页面

## 改动摘要

为系统增加全量操作审计，并支持 SQLCipher 数据库加密。

## audit_logs 表字段

| 字段 | 说明 |
|------|------|
| id | 主键 |
| method | HTTP 方法（POST/PUT/PATCH/DELETE） |
| path | 请求路径 |
| action | 人类可读操作说明（中文） |
| entity_type | 实体类型（task/source_video/material 等） |
| entity_id | 实体 ID（从路径解析） |
| status_code | HTTP 响应状态码 |
| ip_address | 客户端 IP（支持 X-Forwarded-For） |
| user_agent | 浏览器/客户端标识 |
| operator | 操作人名称（来自 X-Operator 请求头） |
| source | 来源：user（HTTP请求）/ system（后台） |
| duration_ms | 接口耗时（毫秒） |
| created_at | 操作时间（UTC） |

## 数据库加密启用步骤

1. 安装 SQLCipher 驱动：`pip install sqlcipher3-binary`
2. 在 `backend/.env` 设置：`DB_ENCRYPTION_KEY=your-strong-passphrase`
3. 重启后端
4. **注意**：已有未加密数据库需先用 `sqlcipher3` CLI 手动加密迁移

## 操作人识别（X-Operator 头）

前端在每个 API 请求中携带 `X-Operator: <名称>` 请求头，后端中间件从该头读取操作人。
前端操作人名称建议存储在 localStorage，并在 Axios 拦截器中统一注入（后续 RBAC 接入后由登录用户替换）。

## 是否需要重启/build

- **后端**：需要重启
- **前端**：dev 模式热更新自动生效；prod 需重新 build
