# ASR 循环递推重试修复记录
- 时间：2026-04-21 13:36:59
- 目标：解决“源视频字幕识别失败”后的恢复能力，新增自动重试、重启续跑与手动重试。

## 问题定位
- 目标条目 `8dacae1527acb76f21c2b6f3224e4fc2.mp4` 当前数据库状态为 `asr_status=completed`，并已有 ASR SRT（4 行）。
- 风险点在于：当条目出现 `failed/pending` 时，缺少稳定的循环递推重试与服务重启后的自动续跑保障。

## 代码改动
- `backend/app/services/asr_service.py`
  - 新增 ASR 自动重试机制（默认最多 3 次，指数退避）。
  - 失败后在上限内自动回到 `pending` 并继续重试。
  - 新增 `resume_pending_asr_jobs`：服务启动自动续跑 `pending/running` 与可重试 `failed` 条目。
  - ASR 输出字幕文件名规则调整：若条目名含扩展名则替换为 `.srt`（避免 `xxx.mp4.srt`）。
- `backend/main.py`
  - 启动阶段增加 `resume_pending_asr_jobs(settings)`。
- `backend/app/api/source_videos.py`
  - 响应增加 `asr_retry_count`、`asr_retry_max`。
  - 新增接口 `POST /api/source-videos/{id}/asr/retry` 手动重试。
- `backend/app/models/source_video_entry.py`
  - 新增字段 `asr_retry_count`、`asr_retry_max`。
- `backend/app/models/database.py`
  - SQLite 兼容迁移新增上述两列。
- `backend/app/schemas/source_video.py`
  - 返回模型补充重试字段。
- `frontend/src/views/SourceVideoLibrary.vue`
  - ASR状态区新增“重试识别”按钮与“重试 x/y”展示。
- `frontend/src/api/sourceVideo.js`
  - 新增 `retrySourceVideoAsr`。
- `frontend/src/store/modules/sourceVideo.js`
  - 新增 `retryAsr` action。
