# 系统设置：ASR / FFmpeg 队列管理

## 改动摘要

在「系统设置」页新增两个面板：
- **ASR 队列**：显示当前所有待处理 / 运行中的 ASR 任务（源视频 + 混剪角色素材），并提供「清空队列」。
- **FFmpeg 队列**：显示当前所有待处理 / 运行中的 FFmpeg 任务（素材插入任务 + 混剪导出），并提供「清空队列」。

每个面板的表头：类型 / 名称 / 状态 / 进度 / 模型（仅 ASR）。点击「清空队列」会弹出确认对话框，说明清空会做什么。

## 清空策略

| 队列 | 待处理 | 运行中 |
|---|---|---|
| ASR | 直接置 `failed`，并把 `asr_retry_count` 顶到上限避免被自动重排 | 标记 `failed`，但实际转写线程会自然结束（CTranslate2 不支持中途中断），结果不会被保留 |
| FFmpeg | 调 `request_stop_task` / `request_stop_project_export`；pending 任务额外置 `stopped` | 终止 `subprocess.Popen`，状态置 `stopped`，可在任务列表手动重启 |

## 是否需要重启 / build

**需要：重启后端 + 前端热更新自动生效**

后端新增了 service 模块和 endpoint，必须重启 uvicorn；前端只动了 `.js` 和 `.vue`，Vite dev server 会自动热更新。

```bash
# 重启后端
./scripts/stop_all.sh && ./scripts/start_all.sh
```

## 验证点

1. 进入「系统设置」页能看到「ASR 队列」「FFmpeg 队列」两个新面板。
2. 当 ASR 在跑（如刚上传源视频 / 混剪做角色 ASR）时，刷新能看到任务条目。
3. 点「清空 ASR 队列」→ 确认 → 队列清零，原本 pending 的源视频条目状态变为 failed，错误信息为「已被用户清空 ASR 队列」。
4. 启动 1 个素材插入任务后点「清空 FFmpeg 队列」→ FFmpeg 子进程被 terminate，任务状态变 stopped。
