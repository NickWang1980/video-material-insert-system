# 任务创建字幕可用性修复记录
- 时间：2026-04-21 16:53:54
- 背景：新建剪辑任务时，源视频已生成可用 SRT（尤其 ASR SRT）仍出现误导提示，且部分历史条目上传 SRT 可用性被误判。

## 本次修复
1. 后端 `source-videos` 可用性判定改为“文件存在优先”
   - `backend/app/api/source_videos.py`
   - `has_uploaded_srt` 从“依赖 subtitle_line_count_user + 文件存在”改为“仅依赖 subtitle_path 文件存在”。
   - 上传字幕路径解析（`source=uploaded`）去掉 `subtitle_line_count_user` 前置依赖，仅按路径与文件存在判断。

2. 任务创建服务上传 SRT 判定修复
   - `backend/app/services/task_service.py`
   - `subtitle_source=uploaded` 时，不再要求 `subtitle_line_count_user` 必须非空；改为仅检查上传 SRT 路径存在且文件存在。

3. 前端任务弹窗提示优化
   - `frontend/src/components/task/CreateTaskModal.vue`
   - `uploadedReady` 回退判定新增 `subtitle_path` 存在即可可用。
   - 文案从“未上传SRT，ASR SRT可用”调整为“ASR SRT 已可用，可直接创建任务”。
   - 自动切换提醒文案改为“将使用 ASR SRT（已就绪）”，避免误导。

## 结果
- 只要条目实际存在可用 SRT 文件（上传或 ASR），任务创建页会按可用状态正确放行。
- 历史条目（`subtitle_line_count_user` 为空但上传 SRT 文件仍在）不再被误判不可用。
